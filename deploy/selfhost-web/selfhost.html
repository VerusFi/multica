    Direct in-tab dashboard access isn't available for this instance: v86's wisp:// network backend (used so the guest can reach the real internet through your relay) has no JavaScript API for this page to open a connection into the guest — only v86's separate fetch backend exposes that, and only one network backend can be active per instance. See this project's dev/NOTES.md ("Task 15") for the full technical writeup.

    Close the console to run a health check — both share the guest's serial console, and a health check sent while you're mid-typing a console command would corrupt it.

    Reach it another way

    1. Click View Console above to get a root shell on the guest over the serial console.
    2. From there you can inspect the running services directly — e.g. curl localhost:3000, rc-status — or use the health check above to confirm the frontend is answering on port 3000 without leaving this page.
    3. A real browser tab pointed at the dashboard needs a TCP path from your machine into the guest's virtual network, which the current relay does not provide — it only relays the guest's own outbound connections, not inbound ones. Not implemented by this build.
